# Telegram 反广告机器人 V2

面向中文社群的自动反广告机器人。核心目标是**在不误删真人的前提下**自动清理群内广告，
并且随着运行时间越长、学到的规则越多，需要 AI 判定的消息越少。

- 运行环境：python-telegram-bot 20.x + SQLite(WAL) + DeepSeek 官方 API
- 部署形态：Docker（`antispam_bot`），单机
- 当前规模：6 个群（最大 5.3 万人）、日均数千条消息

---

## 设计出发点

### 优先级：不能误删真人

广告可以漏（群友会举报、下一波规则会补上），误删真人的代价大得多——
而且撤销不回来。所以整个系统里**每一个自动化决策都先过"会不会误伤"**，
再谈覆盖率。这一点决定了后面几乎所有取舍。

具体的量级参考（来自 SpamAssassin 的成本模型）：误删一封**敏感私人消息**
的代价约等于漏掉 **1000 封**垃圾邮件。

### 规则不是为省钱，是为速度

实测 LLM 判定单次约 **0.0005 元**，钱不是瓶颈。规则真正的价值是**延迟**：
规则 ~0ms 删除，LLM 要等 15-60 秒。所以自进化的目标是
"让广告在出现那一秒消失"，而不是压缩 API 开销。

### 用可信类做约束，而不是用垃圾样本训练

垃圾样本的收集与验证既耗时又易错（文献报告过 0.16% 的错误率），
而**正常消息随手可得且可靠**。所以本系统所有学习机制都用
**"在正常语料上零命中"**作为闸门，而不是"准确率达标"。

## 检测流水线

```
消息到达
  │
  ├─ 管理员 / 白名单 ──────────────────────────► 直接放行
  │
  ├─ L0 确定性规则（~0ms，命中即删）
  │    1. 联系方式本体（手机号/t.me/@bot）—— 含全角数字变体
  │    2. 黑名单用户
  │    3. 不可见字符高占比（实测广告号占 16-60%）
  │    4. 重复刷屏 / 裸字母刷屏（行为类，对所有信任档生效）
  │    5. 判定记忆（管理员裁决过的内容，含归一化变体）
  │    6. 账号资料（昵称即广告位："看我简介"/"主页有群"）
  │    7. 自进化规则（通过零命中闸门 + shadow 观察期的）
  │    8. inline 按钮（广告做成按钮，正文可以完全干净）
  │    9. 外部频道引流（指向非本群体系的 t.me 目标）
  │   10. 协同引流（多账号指向同一预览目标）
  │
  ├─ 免 AI 额度（trusted 用户，5 条）───────────► 放行（但 L0 已跑过）
  │
  ├─ L1 快车道（15s）── 新成员/惯犯/触发条件/波次中
  └─ L2 常规（90s）──── 其余
        │
        └─ LLM 判定（DeepSeek flash，阈值 0.50）
             │
             ├─ 判定记忆写入 / shadow 统计 / 判定记录
             ├─ 删除 + 跨群黑名单（删除达 5 次）
             └─ 举报回填 + 逐条通知（带"误删恢复"按钮）
```

## 关键机制

| 机制 | 解决什么 | 判据/参数 |
|---|---|---|
| **自进化** | 让高频广告不必每次等 AI | 负样本零命中 + shadow 命中 ≥10 + 每日最多毕业 3 条 |
| **波次检测** | 识别协调投放（实测最大 195 条/分钟、105 个账号） | 60s 窗口删除密度 ≥ max(10, 基线×4) |
| **判定记忆** | 人工裁决一次，同类不再打扰 | confirmed 需过零命中闸门；90/365 天过期 |
| **跨群黑名单** | 同一批广告号同时打多个群 | 本群删除 ≥5 次 → 所有群立即生效 |
| **自适应免检** | 老群友闲聊不必每条送 AI | trusted + 8 个触发条件；额度 5 条 |
| **抽样复核** | 让判定质量可测量（否则是"盲信"） | 每日 30 条，**分层抽样向阈值边界倾斜** |
| **审计/健康度** | 回答"为什么删了这条"、发现阈值漂移 | `manage.py audit` / `health` |

## 运维命令

所有运维命令走 CLI（无需 web 后台）：

```bash
# 配置与诊断
python manage.py list                          # 各群配置
python manage.py audit <chat_id> --hours 24    # 审计：某时间窗做了什么决定 + 规则承担率
python manage.py health <chat_id> --hours 24   # 健康度：预测分布/人工推翻率/语料倾斜
python manage.py cost --days 7                 # 成本

# 规则与学习
python manage.py learn <chat_id>               # 自进化状态（候选/过闸/已毕业）
python manage.py learn <chat_id> --run         # 立即跑一轮挖掘与毕业
python manage.py words <chat_id> --add 词       # 词汇表（正常词/禁词）
python manage.py links <chat_id>               # 本群体系的频道标识
python manage.py gbl                           # 全局黑名单（跨群生效）
python manage.py memory                        # 判定记忆（人工裁决复用）
python manage.py previews <chat_id>            # 链路预览指纹（排查协同引流）

# 调参
python manage.py set <chat_id> --threshold 0.6
python manage.py set <chat_id> --token-cap 0   # 0 = 不限
```

## 测试

```bash
python test_pipeline.py     # 33 项回归，覆盖每条防线的边界
```

测试里有几条是**特意记录了"为什么"的回归**，例如：

- 免 AI 额度**不能绕过 L0**（避免"跳过 AI"被误实现成"跳过检查"）
- 行为类检测**不按信任档豁免**（老群友账号被盗后发裸字母同样要拦）
- 自进化统计**按群隔离**（否则一个群能凭别群的证据毕业）
- `normalize` **必须幂等**（否则同一句话有多个指纹，规则/记忆/预览各算一份）
- 判定记忆的闸门**挡住常用短语、放行真广告**

## 部署

```bash
# 服务器：/root/ribaobot/antispambot
# 必须用 --force-recreate：否则 init_db 不跑、新表不会建（踩过）
docker compose up -d --build --force-recreate
docker logs antispam_bot --since 1m      # 启动自检会打印「数据库结构自检通过」
```

配置走 `.env`（`BOT_TOKEN` / `DEEPSEEK_API_KEY` / `ADMIN_ID`），**不入库**。

## 几条来自实战的注意事项

1. **静默失败比崩溃危险。** 自进化曾因为两个 `except: pass` 和一处错误的模块
   回退，**从上线起就没加载过任何规则**——不报错、不崩溃、日志无异常，
   表现为"功能上线了但数据是空的"。凡是 `except: pass` 都该改成显式日志。

2. **同一个算法不要写两遍。** 删除阈值曾在"真正判定"和"举报回填"两处
   各写一遍，只有一处应用了波次收紧——结果是波次期间被采纳的举报
   显示为"已驳回"，而消息其实已经删了。

3. **先量化再决定。** 本项目的多数"看起来该做"的功能最后都被数据否掉了：
   贝叶斯分类器（F1 0.76 vs LLM 0.92）、CAS 跨群黑名单（覆盖率 0%）、
   西里尔同形字映射（线上零滥用）、一次性账号信号（删除率反而更低）。
   详见 `docs/cross-platform-notes.md`。
